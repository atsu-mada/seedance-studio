生成の引継ぎと観測した状態

保存した計画と、プロバイダーへ実際に渡した入力を分けて照合する。送信前の準備、送信の許可、受理、生成中、完了、ファイル取得、技術QC、知覚レビュー、採用は別の状態である。自動的なスキル選択は有料生成や投稿への実行承認を追加しない。

実際の入力を記録する

  • プロンプトの版と実際の文面。
  • 参照の順序、実際のタグ、各参照が担う役割と除外する属性。
  • 開始・終了フレームの指定有無と対象。
  • 対象surface、モデル、尺、画角、画質、音声、課金やモードの実表示。
  • 受理されたジョブID、観測日時、完了/失敗表示、取得したファイルと検査結果。

記録された過去の秒数・枚数・料金・モードを現在の一般上限としない。現在の機能を説明する必要があれば source gate を通す。具体的なクリック・アップロード・送信は対象プロバイダーの実行手順へ渡す。

既存generation-runへ付ける任意情報

項目表すこと
provider_statusunknown / queued / processing / completed / failed
technical_qcnot_checked / pass / fail。実ファイルの技術検査。
perceptual_reviewpending / pass / fail / uncertain。映像・音の観測判断。
review_evidence作品内相対パスで示す検査・レビュー根拠。

4つの任意情報を持たない旧記録は互換のまま保ち、欠落値をpassで補完しない。任意情報を1つでも使うaccepted記録では、provider_status=completed、technical_qc=pass、perceptual_review=passをすべて要求する。review_evidenceは任意だが、記載する場合は相対パスの配列として検査する。Processingは既存の result_status=submitted に provider_status=processing を添える。completedだけでacceptedへ進めない。記載されたQCや知覚レビューが不合格・未確認ならacceptedと矛盾する。take-reviewは実際に評価した後で作る。別の重複台帳を追加しない。

再開時

同じジョブが処理中かを先に確認して重複送信を避ける。継続プロンプトは、採用された前クリップの実際の終端から組む。保存済みプロンプトの予定終端を、観測済みの事実に置き換えない。
